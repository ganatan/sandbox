# Ganatan — Comprendre la programmation, construire avec l'intelligence artificielle

## Introduction

L'intelligence artificielle transforme profondément la manière de concevoir et de développer les logiciels.

Pendant longtemps, développer une application signifiait principalement écrire du code.

Le développeur analysait un problème, définissait les règles nécessaires, puis écrivait les instructions permettant à l'ordinateur de les exécuter.

Aujourd'hui, les assistants d'intelligence artificielle comme ChatGPT ou Claude permettent de produire du code, de proposer des architectures, d'écrire des tests et de générer de la documentation.

Cette évolution soulève une question fondamentale :

**Est-il encore nécessaire d'apprendre à programmer lorsque l'intelligence artificielle peut produire le code ?**

La démarche Ganatan repose sur une réponse simple.

Il n'est plus indispensable d'écrire personnellement chaque instruction pour construire certaines applications.

Mais il reste essentiel de comprendre les principes fondamentaux du développement logiciel afin de prendre les bonnes décisions et de vérifier les résultats.

**Comprendre pour décider. Utiliser l'IA pour construire. Vérifier pour maîtriser.**

# 1. La programmation traditionnelle

## 1.1. Comment fonctionne un programme traditionnel ?

La programmation traditionnelle consiste à écrire explicitement les instructions qu'un ordinateur doit exécuter.

Le développeur définit les règles du programme.

L'ordinateur applique ces règles aux données reçues.

Le fonctionnement général peut être représenté ainsi :

```text
Règles écrites par le développeur
                +
              Données
                |
                v
             Programme
                |
                v
              Résultat
```

Prenons une application de cinéma.

Nous voulons retrouver tous les films sortis après 2010.

Nous pouvons écrire une requête SQL qui sélectionne les films dont l'année de sortie est supérieure à 2010.

Nous voulons calculer la durée moyenne des films.

Nous pouvons écrire un algorithme qui additionne les durées et divise le résultat par le nombre de films.

Nous voulons vérifier qu'une date est valide.

Nous pouvons définir des règles précises.

Dans ces situations, la programmation traditionnelle reste parfaitement adaptée.

Le problème est connu.

Les règles sont explicites.

Le résultat peut être vérifié.

## 1.2. Les limites de la programmation traditionnelle

Certains problèmes sont beaucoup plus difficiles à traduire en instructions.

Comment reconnaître un visage dans une photographie ?

Comment comprendre une phrase formulée en français ?

Comment reconnaître un objet dans une image ?

Comment déterminer si deux textes possèdent un sens similaire ?

Un humain peut réaliser certaines de ces tâches intuitivement.

Mais il est extrêmement difficile d'écrire toutes les règles nécessaires pour les reproduire.

C'est dans ce contexte que les techniques d'apprentissage automatique sont devenues particulièrement importantes.

# 2. Comprendre l'intelligence artificielle

## 2.1. Qu'est-ce que l'intelligence artificielle ?

L'intelligence artificielle est un domaine de l'informatique qui cherche à construire des systèmes capables de réaliser des tâches associées à certaines formes d'intelligence.

Ces tâches peuvent notamment comprendre :

- La reconnaissance d'images.
- Le traitement du langage.
- La reconnaissance vocale.
- La classification de données.
- La prédiction.
- La planification.
- La génération de contenus.
- L'aide à la décision.

L'intelligence artificielle ne désigne pas une technologie unique.

Elle regroupe plusieurs approches.

Certaines reposent sur des règles explicites.

D'autres reposent sur des méthodes statistiques ou sur l'apprentissage automatique.

## 2.2. Qu'est-ce que l'apprentissage automatique ?

L'apprentissage automatique, ou *machine learning*, est une branche de l'intelligence artificielle.

Son principe consiste à permettre à un système d'apprendre des régularités à partir de données.

Au lieu de programmer explicitement toutes les règles, nous utilisons un algorithme d'apprentissage pour ajuster les paramètres d'un modèle.

Le fonctionnement peut être simplifié ainsi :

```text
      Données d'entraînement
                |
                v
     Algorithme d'apprentissage
                |
                v
          Modèle entraîné
                |
                v
          Nouvelles données
                |
                v
       Prédiction ou réponse
```

L'algorithme d'apprentissage est lui-même conçu et programmé par des humains.

Il sert à construire ou ajuster un modèle mathématique.

Ce modèle peut ensuite être utilisé pour analyser de nouvelles données.

## 2.3. Programmation traditionnelle et apprentissage automatique

La différence fondamentale concerne la manière dont les règles sont obtenues.

### Programmation traditionnelle

Le développeur écrit les règles.

Le programme applique ces règles aux données.

### Apprentissage automatique

Le développeur choisit une méthode d'apprentissage.

Le système utilise des données pour ajuster un modèle.

Le modèle produit ensuite des prédictions ou des réponses.

Ces deux approches ne sont pas incompatibles.

Elles sont complémentaires.

Une application moderne peut parfaitement utiliser des algorithmes traditionnels et des modèles d'intelligence artificielle.

**L'apprentissage automatique ne supprime pas la programmation. Il introduit une autre manière de construire certains comportements logiciels.**

# 3. Les progrès de l'intelligence artificielle

## 3.1. Une évolution majeure

Pendant longtemps, l'intelligence artificielle était principalement utilisée pour résoudre des problèmes spécialisés.

Par exemple :

- Reconnaître des caractères.
- Identifier des objets.
- Classer des documents.
- Analyser des images médicales.
- Détecter certaines anomalies.
- Effectuer des prédictions statistiques.

Avec les progrès de l'apprentissage profond et des grands modèles de langage, ses possibilités se sont considérablement élargies.

Des systèmes comme ChatGPT et Claude peuvent désormais produire du texte, expliquer des concepts et assister de nombreuses tâches intellectuelles.

Ils peuvent également participer directement au développement logiciel.

## 3.2. L'IA devient un outil de développement

Aujourd'hui, un assistant d'intelligence artificielle peut notamment :

- Expliquer un langage de programmation.
- Générer du code TypeScript.
- Construire des composants Angular.
- Proposer une architecture logicielle.
- Créer des routes Express.
- Écrire des requêtes PostgreSQL.
- Générer des tests.
- Analyser des messages d'erreur.
- Proposer des corrections.
- Produire de la documentation.
- Préparer des procédures de déploiement.

L'intelligence artificielle ne se limite donc plus à certaines fonctionnalités particulières des applications.

Elle intervient également dans la construction des applications elles-mêmes.

C'est une évolution fondamentale.

## 3.3. Le développeur n'écrit plus nécessairement tout le code

Traditionnellement, le développeur devait traduire chaque besoin en instructions.

Avec un assistant IA, il peut décrire le résultat attendu.

L'assistant peut proposer une implémentation.

Le développeur peut ensuite examiner, corriger et valider cette implémentation.

Le processus devient :

```text
            Besoin
               |
               v
       Analyse du problème
               |
               v
        Choix techniques
               |
               v
       Instructions à l'IA
               |
               v
         Code généré
               |
               v
       Analyse et validation
               |
               v
          Application
```

Cette démarche peut accélérer considérablement certaines tâches.

Mais elle ne garantit pas automatiquement la qualité du résultat.

# 4. Les limites de l'intelligence artificielle

## 4.1. Le besoin de données

Les grands modèles modernes sont généralement entraînés à partir de très grandes quantités de données.

Leur entraînement peut nécessiter des ressources informatiques considérables.

Cette phase peut être extrêmement coûteuse.

Il faut cependant distinguer trois opérations.

### Entraîner un modèle

Il s'agit de construire ou d'ajuster un modèle à partir de données d'entraînement.

### Adapter un modèle

Il est parfois possible d'adapter un modèle existant à une tâche particulière.

### Utiliser un modèle

Il s'agit d'interroger un modèle déjà entraîné afin d'obtenir une réponse.

Dans notre démarche Ganatan, nous utiliserons principalement des modèles existants.

Nous ne chercherons pas à entraîner notre propre grand modèle de langage.

Notre objectif est d'utiliser l'intelligence artificielle comme un outil de développement.

## 4.2. Le problème de la boîte noire

Un programme traditionnel possède des instructions explicites.

Nous pouvons examiner ses conditions, ses boucles, ses fonctions et ses calculs.

Nous pouvons généralement suivre son exécution et comprendre les mécanismes qui produisent un résultat.

Les modèles d'apprentissage profond fonctionnent différemment.

Ils peuvent contenir des millions ou des milliards de paramètres numériques.

Ces paramètres sont ajustés pendant l'entraînement.

Même lorsque nous connaissons les opérations mathématiques exécutées, il peut être difficile d'expliquer précisément pourquoi le modèle produit une réponse particulière.

C'est ce que nous appelons le problème de la **boîte noire**.

Il existe des méthodes permettant d'étudier et d'interpréter les modèles.

Mais elles ne fournissent pas toujours une explication complète et fiable de chaque résultat.

## 4.3. Une distinction essentielle

Il faut distinguer deux choses.

Le code généré par une IA peut être parfaitement compréhensible.

Un programme TypeScript généré par ChatGPT peut être lu, exécuté, testé et analysé.

En revanche, le fonctionnement interne du modèle qui a généré ce code est beaucoup moins directement interprétable.

Cette distinction est fondamentale.

**Utiliser une IA pour produire du code ne signifie pas que le code produit devient une boîte noire.**

Nous pouvons conserver la maîtrise du logiciel généré.

À condition de prendre le temps de le comprendre et de le vérifier.

## 4.4. L'IA peut produire des erreurs

Un assistant d'intelligence artificielle peut proposer une solution incorrecte.

Il peut notamment :

- Générer du code qui ne compile pas.
- Utiliser une API inexistante.
- Oublier une validation.
- Produire une requête SQL inefficace.
- Introduire une faille de sécurité.
- Proposer une architecture trop complexe.
- Oublier certains cas particuliers.
- Produire des tests insuffisants.

Une réponse convaincante n'est pas nécessairement correcte.

Il faut donc vérifier les résultats.

Les tests, les validations et la compréhension du fonctionnement restent indispensables.

# 5. La fin du développement traditionnel ?

## 5.1. Une question légitime

Si l'intelligence artificielle peut produire du code, pourquoi continuer à apprendre la programmation ?

Allons-nous passer d'un monde de développeurs à un monde d'utilisateurs d'intelligence artificielle ?

Il faut distinguer la disparition de certaines tâches et la disparition d'un métier.

L'intelligence artificielle automatise déjà une partie du travail qui nécessitait auparavant une écriture manuelle du code.

Cette automatisation pourrait continuer à progresser.

Mais construire un logiciel ne consiste pas uniquement à écrire des instructions.

Il faut également comprendre le besoin, concevoir le système, organiser les données, vérifier les résultats et assurer la maintenance.

## 5.2. Le rôle du développeur évolue

| Développement traditionnel | Développement assisté par IA |
|---|---|
| Écrire les traitements | Décrire les traitements et vérifier leur génération |
| Construire les composants | Concevoir et faire produire les composants |
| Rechercher les erreurs | Utiliser l'IA pour aider au diagnostic |
| Écrire les tests | Générer et vérifier les tests |
| Produire la documentation | Générer et maintenir la documentation |
| Réaliser les choix techniques | Réaliser les choix techniques |

La dernière ligne est particulièrement importante.

L'intelligence artificielle peut proposer des décisions techniques.

Mais elle ne connaît pas automatiquement toutes les contraintes réelles d'un projet.

Elle peut également proposer des solutions disproportionnées.

Le développeur doit donc conserver sa capacité à analyser et à décider.

## 5.3. Une évolution des compétences

Le développeur de demain pourrait consacrer davantage de temps :

- À l'analyse des besoins.
- À la conception.
- Aux choix technologiques.
- À l'architecture.
- À la validation.
- Aux tests.
- À la sécurité.
- À l'intégration.
- À la maintenance.

Il n'aura pas nécessairement besoin de mémoriser toutes les subtilités de chaque langage ou framework.

Mais il devra comprendre suffisamment les fondamentaux pour évaluer les solutions produites.

**La capacité à juger un résultat devient aussi importante que la capacité à le produire.**

# 9. POC, MVP et application de référence

## 9.1. POC — Proof of Concept

Un POC est une preuve de concept.

Il sert à démontrer qu'une solution est techniquement réalisable.

Il répond à la question :

**Est-ce que cela peut fonctionner ?**

Pour Ganatan, notre POC consistera à vérifier qu'Angular peut communiquer avec Express et PostgreSQL.

Une seule fonctionnalité peut suffire.

## 9.2. MVP — Minimum Viable Product

Un MVP est un produit minimum viable.

Il constitue une première version utilisable d'un produit.

Il doit permettre de répondre à un besoin réel et d'obtenir des retours.

Pour Ganatan, le MVP comprendra les fonctionnalités essentielles de nos quatre entités.

Nous pourrons consulter les données, rechercher des médias et effectuer les opérations nécessaires.

Le MVP n'a pas besoin de contenir toutes les fonctionnalités imaginables.

## 9.3. Application de référence

Après le MVP, nous consoliderons le projet.

Nous améliorerons notamment :

- Les validations.
- Les tests.
- La sécurité.
- La documentation.
- La gestion des erreurs.
- Le déploiement.
- La maintenance.

Nous ne construisons pas trois applications différentes.

Nous faisons évoluer progressivement le même projet.

```text
               POC
                |
                v
               MVP
                |
                v
      Application de référence
```

Cette progression permet de maîtriser la complexité.

# 10. Le risque de suringénierie avec l'IA

## 10.1. La facilité de générer du code

Les assistants IA peuvent produire rapidement de grandes quantités de code.

C'est un avantage considérable.

Mais cette facilité présente également un risque.

Il devient très simple d'ajouter des fonctionnalités, des abstractions et des dépendances.

Une application qui devait être simple peut progressivement devenir difficile à comprendre.

## 10.2. Un exemple

Nous demandons à une IA de créer une API permettant de gérer des pays.

Elle pourrait proposer :

- Plusieurs couches d'abstraction.
- Des interfaces génériques.
- Un système de cache.
- Une architecture événementielle.
- Des services indépendants.
- Une infrastructure de messagerie.
- Des dizaines de fichiers.

Ces éléments peuvent être utiles dans certains projets.

Mais ils seraient disproportionnés pour notre besoin.

La complexité technique ne constitue pas une preuve de qualité.

## 10.3. Les règles Ganatan

Nous retiendrons quelques principes simples.

- Une base PostgreSQL.
- Quatre entités principales.
- Un frontend Angular.
- Une API Express.
- Une architecture en couches compréhensible.
- Un déploiement DigitalOcean.
- Des dépendances limitées.
- Des tests adaptés aux risques.
- Aucun composant supplémentaire sans besoin identifié.

L'IA devra respecter ces contraintes.

Elle ne devra pas redéfinir l'architecture à chaque génération.

## 10.4. Les design patterns

Nous expliquerons l'histoire et le rôle des design patterns.

Nous présenterons notamment les 23 patrons du Gang of Four, répartis en trois familles :

- Création.
- Structure.
- Comportement.

Mais nous ne chercherons pas à les utiliser artificiellement.

Un patron de conception doit répondre à un problème réel.

Nous privilégierons la séparation des responsabilités, un couplage maîtrisé et une structure facilement compréhensible.

Nous éviterons une architecture hexagonale complète ou des microservices si leur complexité n'est pas justifiée.

**L'IA peut produire de la complexité beaucoup plus vite que nous ne pouvons la comprendre. Notre responsabilité est de contrôler cette complexité.**

# 13. La philosophie Ganatan

Pendant longtemps, apprendre à développer signifiait principalement apprendre à écrire du code.

Avec les progrès de l'intelligence artificielle, il devient possible de construire certaines applications sans écrire personnellement chaque instruction.

Mais cela ne supprime pas la nécessité de comprendre les systèmes informatiques.

Au contraire, cette compréhension permet de mieux formuler les demandes, de choisir les bonnes solutions, de reconnaître les erreurs et de limiter la complexité.

Ganatan propose donc une démarche pragmatique.

**Comprendre suffisamment la programmation traditionnelle pour maîtriser les décisions, puis utiliser l'intelligence artificielle pour accélérer la réalisation.**

Nous n'avons pas besoin de construire une application gigantesque.

Nous n'avons pas besoin de maîtriser toutes les technologies.

Nous n'avons pas besoin d'utiliser tous les design patterns.

Nous avons besoin :

- D'un problème clair.
- D'un objectif limité.
- D'une architecture cohérente.
- D'outils adaptés.
- De critères de qualité explicites.
- D'une méthode de vérification.
- D'une application réellement utilisable.

Notre application de médias servira à démontrer cette démarche.

# 14. Conclusion

Ganatan.com ne sera plus uniquement un site consacré aux tutoriels Angular.

Il deviendra une démonstration concrète d'une nouvelle manière d'aborder le développement logiciel.

Nous commencerons par comprendre les concepts fondamentaux.

Nous expliquerons les langages, les bases de données, les architectures et les patrons de conception.

Nous présenterons les raisons de nos choix.

Nous utiliserons ensuite l'intelligence artificielle pour construire progressivement une application réelle.

Cette application restera volontairement simple.

Elle reposera sur quatre entités :

- Country.
- City.
- Person.
- Media.

Elle utilisera une stack technique limitée :

- ChatGPT.
- TypeScript.
- Angular.
- Node.js.
- Express.
- PostgreSQL.
- DigitalOcean.

Nous commencerons par un POC.

Nous construirons ensuite un MVP.

Nous consoliderons enfin une application de référence.

Nous éviterons la suringénierie, les dépendances inutiles et les architectures disproportionnées.

Nous chercherons à produire un logiciel compréhensible, maintenable et correctement déployé.

L'objectif n'est pas de remplacer la réflexion par l'automatisation.

Il est d'utiliser l'automatisation au service d'une réflexion technique maîtrisée.
